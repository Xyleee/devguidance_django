================================================================================
                              KEY RELATIONSHIPS
================================================================================

1. USER ↔ STUDENT PROFILE (One-to-One)
   • Each user can have one student profile
   • Profile extends user with student-specific data

2. USER ↔ MENTOR PROFILE (One-to-One)  
   • Each user can have one mentor profile
   • Profile extends user with mentor-specific data

3. STUDENT PROFILE → STUDENT PROJECT (One-to-Many)
   • Each student can have multiple projects
   • Projects belong to one student

4. USER → MENTORSHIP REQUEST (One-to-Many, bidirectional)
   • As Student: User can send multiple mentorship requests
   • As Mentor: User can receive multiple mentorship requests

5. USER → MESSAGE (One-to-Many, bidirectional)
   • As Sender: User can send multiple messages
   • As Receiver: User can receive multiple messages

================================================================================
                               BUSINESS RULES
================================================================================

🔐 AUTHENTICATION & AUTHORIZATION:
   • JWT-based authentication with access/refresh tokens
   • Role-based permissions (Student, Mentor, Owner)
   • Rate limiting on authentication endpoints

👥 USER MANAGEMENT:
   • Users can be either Students OR Mentors (not both)
   • Profile creation is automatic on user registration
   • Unique usernames and emails enforced

📝 MENTORSHIP WORKFLOW:
   • Students browse mentors by expertise
   • Students send mentorship requests with messages
   • Mentors can accept/decline with optional reasons
   • Only one active mentorship per student
   • Accepting a request auto-declines others

💬 MESSAGING SYSTEM:
   • Real-time messaging between users
   • File attachments with validation
   • Message history and read status
   • Only connected users can message

📊 DATA INTEGRITY:
   • Cascade deletes prevent orphaned records
   • Unique constraints prevent duplicates
   • JSON fields for flexible data storage
   • Automatic timestamps for audit trails

================================================================================
                            INDEXING STRATEGY
================================================================================

🚀 PERFORMANCE OPTIMIZATION:

PRIMARY INDEXES (Auto-created):
   • User.id, StudentProfile.id, MentorProfile.id, etc.

UNIQUE INDEXES:
   • User.username, User.email (Django built-in)
   • (StudentProfile.user_id), (MentorProfile.user_id)

RECOMMENDED CUSTOM INDEXES:
   • MentorshipRequest.status (for filtering)
   • MentorshipRequest.student + MentorshipRequest.mentor (composite)
   • Message.timestamp (for ordering)
   • Message.sender + Message.receiver (for conversations)
   • StudentProfile.tech_stack (GIN index for JSON queries)
   • MentorProfile.expertise_tags (GIN index for JSON queries)

================================================================================
                          DATABASE NORMALIZATION
================================================================================

✅ FIRST NORMAL FORM (1NF):
   • All attributes contain atomic values
   • No repeating groups or arrays in scalar fields
   • JSON fields used appropriately for complex data

✅ SECOND NORMAL FORM (2NF):
   • All non-key attributes fully depend on primary keys
   • No partial dependencies exist

✅ THIRD NORMAL FORM (3NF):
   • No transitive dependencies
   • All non-key attributes depend only on primary keys

📈 BENEFITS OF NORMALIZATION:
   • Eliminates data redundancy
   • Prevents update anomalies
   • Ensures data consistency
   • Supports efficient queries
   • Maintains referential integrity
